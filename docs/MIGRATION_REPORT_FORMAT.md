# Migration and Verification Report Format

The cutover tools write machine-readable JSON reports so a migration can be reviewed, resumed, and audited without relying on console output.

## Migration report

Generated by:

```bash
python scripts/migrate_sqlite_to_postgres.py \
  --sqlite data/procureflow_workspace.db \
  --report data/backups/cloudsql_migration/migration_report.json
```

The report contains:

- UTC start/completion timestamps and duration;
- source SQLite path and pre-migration backup path;
- source, migrated, and failed row counts for every table;
- the primary/unique conflict key used for restart-safe upserts;
- per-table `ok`, `partial`, or missing-destination status;
- every failed source record, including table, source key, error type, and a bounded error message;
- overall `success` or `partial` status.

A `partial` result exits with status code 2 and must not be cut over until each failed record is resolved and the migration is rerun.

## Verification report

Generated by:

```bash
python scripts/verify_database_migration.py \
  --sqlite data/procureflow_workspace.db \
  --report data/backups/cloudsql_migration/verification_report.json
```

The verification report contains:

- source/destination counts and match state for every table;
- byte-for-byte migrated password-hash comparison;
- orphan counts for critical workflow relationships;
- document-reference counts and examples missing from the current host;
- a complete error list and overall `passed` or `failed` status.

After the report passes, rerun with `--validate-constraints` to validate the deferred PostgreSQL foreign keys. Preserve the final migration and verification reports with the cutover backup and deployment record.

## Document migration report

`scripts/migrate_document_storage.py` records copied, checksum-reused, missing, and failed document references plus the number of PostgreSQL path rows updated. A partial result exits with status code 2 and blocks cutover.
